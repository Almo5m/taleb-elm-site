# ملاحظاتي — موقع طالب علم

الموقع static بالكامل، مفيهوش build ولا npm ولا حاجة — بترفعه زي ما هو وخلاص.
من بعد ما اتقسّم، بقى شكل الملفات كده:

```
index.html                  ← الهيكل (HTML) بس، حوالي 570 سطر
assets/
  css/
    main.css                ← كل تنسيق الموقع (كان جوه <style> في index.html)
  js/
    config.js                ← الإعدادات (APK_URL, SUPABASE_URL...) + معرّف الزائر
    analytics.js              ← تتبّع الزوار
    updates.js                 ← قائمة "آخر التحديثات" (APP_UPDATES) وعرضها
    reviews.js                  ← نظام التقييمات (عرض + إرسال)
    ui.js                        ← كل تفاعلات الواجهة (مودالات، سكرول، نافيجيشن...)
    demo.js                       ← ويدجت "جرّب دلوقتي" (عداد بومودورو حقيقي + قائمة مهام تفاعلية)
  screenshots/                 ← سكرين شوتات التطبيق الحقيقية
analytics/
  dashboard-x7k29.html        ← لوحة الإحصائيات الخاصة (الهيكل بس)
  dashboard.css                ← تنسيق اللوحة
  dashboard.js                  ← منطق اللوحة كامل
  supabase-setup*.sql            ← ملفات إعداد قاعدة البيانات (شغّلهم بالترتيب المكتوب في كل واحد)
```

**قاعدة مهمة:** ملفات الـ JS في `assets/js/` لازم تتحمّل بنفس الترتيب المكتوب في
`index.html` (`config.js` أول حاجة، وبعدين `analytics.js` → `updates.js` → `reviews.js` →
`ui.js` آخر واحد) — لأن كل ملف بيستخدم متغيرات أو دوال من اللي قبله (زي `SUPABASE_URL`
و`getVisitorId()` من `config.js`). لو نقلت سكريبت مكانه في الـ `<head>` أو غيّرت الترتيب،
ممكن حاجات تبوظ. نفس الكلام في `analytics/dashboard-x7k29.html` بس فيه ملف JS واحد بس.

## لو عايز أحدّث لينك الـ APK
افتح `assets/js/config.js`، أول سطر فيه:
```js
const APK_URL = "ضع_رابط_تحميل_الـ_APK_هنا";
```
غيّر القيمة بلينك الـ release الجديد من GitHub، وخلاص — كل زراير التحميل في الموقع
(فوق، ونص الصفحة، وقسم الـ CTA) هتستخدم نفس اللينك تلقائي، مش محتاج أغيّره في أكتر من مكان.

## إزاي شغالة نافذة التحذير
أي زرار "حمّل التطبيق" في الموقع (مش لينك مباشر) بيفتح نافذة فيها صورة رسالة "Play للحماية"
وخطوتين الحل، وبعدين زرار "حمّل الملف الآن" هو اللي فعليًا بيودي على `APK_URL`. يعني حد
يقدر يشوف الملف ينزل من غير ما يقرا التنويه الأول. الكود ده كله في `assets/js/ui.js`.

## الملفات اللي لازم أرفعها كلها مع بعض (مش index.html بس)
`favicon-32.png`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, `og-image.png`
ومجلد `assets/` بالكامل (بما فيه `css/` و`js/` دلوقتي، مش بس الصور)، و`analytics/` بالكامل
لو عايز التتبّع والتقييمات يشتغلوا.

## نشر على GitHub Pages
في الريبو: Settings → Pages → اختار الفرع `main` والمجلد `/root` (أو `/`) → Save.
هياخدلك شوية دقايق وبعدين يديني رابط زي `username.github.io/repo-name`.

## تتبّع الزوار (Supabase)
الموقع فيه تتبّع بسيط وخاص لأربع أحداث: زيارة الصفحة، وصول المستخدم لمرحلة التحميل
(فتح نافذة تحذير Play للحماية)، التحميل الفعلي، ومتابعة قناة الواتساب.

**الإعداد (مرة واحدة بس):**
1. شغّل ملف `analytics/supabase-setup.sql` كامل في Supabase Dashboard → SQL Editor.
   غيّر كلمة `غيّر_الباسورد_ده_CHANGE_ME` الموجودة مرتين جوه الملف لباسورد من عندك قبل ما تشغّله.
2. في `assets/js/config.js`، حط بيانات مشروعك:
   ```js
   const SUPABASE_URL = "...";
   const SUPABASE_ANON_KEY = "...";
   ```
3. نفس الاتنين لازم يتحطّوا كمان في `analytics/dashboard.js`.

**عشان تشوف الأرقام:** افتح `analytics/dashboard-x7k29.html` وادخل بالباسورد اللي حطيته
في الـ SQL. الصفحة دي مش متلينكة من أي مكان في الموقع ومحمية بباسورد بيتشيك عليه من جوه
Supabase نفسه (function بـ `security definer`)، يعني حتى لو حد لقط مفتاح الـ anon من كود
الموقع (وهو أصلًا ظاهر لأي حد بيفتح الموقع بالتصميم) مش هيقدر يقرا بيانات الزوار من غيره.
سيب اسم الملف زي ما هو ومتحطهوش في أي لينك أو نافيجيشن.

## نظام التقييمات (Supabase)
قسم "آراء الطلاب" بيسمح لأي زائر يبعت تقييم (اسم + نجوم + تعليق اختياري)، لكن التقييم
مابيظهرش للعامة إلا بعد ما توافق عليه من لوحة الإحصائيات الخاصة.

**الإعداد (مرة واحدة بس، بعد إعداد التتبّع فوق):**
1. شغّل ملف `analytics/supabase-setup-reviews.sql` كامل في SQL Editor. ملف منفصل تمامًا
   عن تتبّع الزوار، وميأثرش على جدول `site_events` ولا بياناته.
2. غيّر كلمة `غيّر_الباسورد_ده_CHANGE_ME` الموجودة مرتين جوه الملف — استخدم **نفس الباسورد**
   اللي حطيته في `supabase-setup.sql`، عشان توافق على التقييمات من نفس لوحة الإحصائيات
   بنفس الباسورد.
3. بيانات Supabase (`SUPABASE_URL` و`SUPABASE_ANON_KEY`) نفس المتغيرات اللي حطيتها بالفعل
   في `assets/js/config.js` و`analytics/dashboard.js`، مفيش حاجة زيادة تحطها هنا.

**إزاي تراجع التقييمات:** في `dashboard-x7k29.html`، دوس على تبويب "⭐ التقييمات" فوق —
هتلاقي عدّاد بيوريك عدد التقييمات المحتاجة مراجعة، وتقدر "تنشر" أو "تحذف" كل تقييم لوحده.
بعد النشر التقييم بيظهر فورًا في قسم "آراء الطلاب" بالموقع.

## صفحة تقييم مستقلة (`rate.html`)
عشان تبقى في إيدك طريقة أسهل تبعتها لأي حد يقيّم من غير ما يدخل الموقع كله، فيه ملف
`rate.html` منفصل — صفحة بسيطة فيها بس نجوم كبيرة سهلة الضغط + اسم + تعليق اختياري،
وبتبعت لنفس نظام التقييمات (`submit_review`) بالظبط، يعني هتظهر في نفس مكان المراجعة
في لوحة الإحصائيات زي أي تقييم تاني.

**اللينك اللي تبعته للناس** (بعد ما ترفع الموقع):
```
https://almo5m.github.io/taleb-elm-site/rate.html
```

مفيش أي إعداد إضافي مطلوب — الصفحة دي بتستخدم نفس بيانات Supabase المكتوبة جواها
مباشرة (مطابقة لنفس القيم في `assets/js/config.js`). لو غيّرت مفتاح Supabase يومًا،
فاكر تحدّثه في الملفين مع بعض.

## توثيق التقييمات (شارة "✅ اتأكدنا إنه حمّل")
عشان أي حد ميقدرش يكتب تقييم وهمي بسهولة، في طبقة تحقق خفيفة: كل تقييم بيتربط
بنفس "معرّف الزائر" العشوائي المستخدم أصلًا في تتبّع الزوار. لو نفس المعرّف ده
سبق ودوّس زرار "حمّل الملف الآن" فعليًا، التقييم بياخد شارة توثيق خضرا في الموقع
وفي لوحة المراجعة. مفيش تسجيل دخول ولا بيانات شخصية إضافية — نفس الفكرة اللي
شغالة أصلًا في الإحصائيات.

**الإعداد (خطوة واحدة زيادة، بعد الخطوات اللي فوق):**
1. شغّل ملف `analytics/supabase-setup-verified-reviews.sql` كامل في SQL Editor.
   الملف ده بيضيف عمودين لجدول التقييمات (`visitor_id`, `verified`) وبيقفل باب
   الإدخال المباشر للجدول بحيث كل تقييم لازم يعدّي من دالة تحقق واحدة.
2. مفيش باسورد أو إعدادات زيادة — الملف بيشتغل تلقائي مع نفس بيانات Supabase
   المستخدمة بالفعل.

ملحوظة: التوثيق ده مش "إثبات قاطع" إن الشخص فعلاً بيستخدم التطبيق — هو بس تأكيد
إنه فتح نفس المتصفح ودوّس تحميل قبل ما يكتب تقييم، وده كافي إنه يفلتر أي حد بيكتب
تقييم عشوائي من غير ما يزور صفحة التحميل خالص. تقييم واحد بس مسموح لكل زائر
(لو بعت تاني بيتحدث القديم بدل ما يتكرر).

**تحديث "آخر التحديثات":** مع كل نسخة جديدة من التطبيق، عدّل مصفوفة `APP_UPDATES` في أول
`assets/js/updates.js` — ضيف عنصر جديد فوق القايمة وسيب `latest: true` عليه بس،
وشيلها من اللي قبله.

## حاجات أفتكرها
- الخطوط بتتحمل أونلاين من Google Fonts، فمحتاج نت عادي وقت فتح الصفحة بس.
- الموقع static بالكامل، وبيبعت بس أحداث تتبّع مجهولة (بدون أي بيانات شخصية) لـ Supabase
  لو حطيت بياناته، وبيتجاهلها تلقائي لو سبتها فاضية.
- الهوية الجديدة مبنية على شكل التطبيق نفسه بالظبط (خلفية فاتحة، بطاقات بيضا، أخضر أساسي،
  كمان الألوان الفاتحة لكل مادة زي ما هي في شاشة "المواد") — عشان لما حد يشوف الموقع بعدين
  يفتح التطبيق يحس إنه نفس الحاجة، مش حاجتين مختلفين.
